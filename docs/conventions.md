# قواعد التسمية والتنظيم - المرحلة 0

## 1) قواعد تسمية الملفات
- HTML: أسماء قصيرة بصيغة kebab-case أو اسم صفحة مباشر (مثل: `index.html`, `login.html`).
- JavaScript: أسماء بصيغة kebab-case (مثل: `supabase-client.js`).
- CSS: تقسيم حسب المسؤولية (`utilities.css`, `components.css`, `app.css`).

## 2) قواعد JavaScript
- استخدام ES Modules فقط (`import/export`).
- كل ملف له مسؤولية واحدة واضحة.
- أسماء الدوال: camelCase وبشكل يشرح الهدف (`testSupabaseConnection`).
- لا توضع مفاتيح حساسة في الواجهة الأمامية.
- التعامل الدفاعي مع الأخطاء وإظهار رسائل عربية واضحة للمستخدم.

## 3) قواعد CSS
- `utilities.css`: متغيرات عامة ومساعدات بسيطة.
- `components.css`: مكونات واجهة قابلة لإعادة الاستخدام.
- `app.css`: تنسيقات الصفحة العامة والاستجابات.
- التصميم Mobile-first أولاً ثم تحسين الشاشات الأكبر.

## 4) قواعد HTML
- كل صفحة تبدأ بـ `lang="ar"` و `dir="rtl"`.
- استخدام هيكل واضح: `header` ثم `main`.
- الاعتماد على Bootstrap RTL مع تحسينات مخصصة خفيفة.

## 5) اتفاقيات للمراحل القادمة
- إضافة أي ميزة جديدة داخل مجلد مخصص (مثال: `assets/js/modules/<feature>`).
- منع تكرار الأكواد المشتركة: انقلها إلى `utils/` أو `ui/`.
- أي تكامل خارجي يجب أن يمر من طبقة `services/`.
- قبل الانتقال لمرحلة جديدة: تأكد من عدم وجود أخطاء Console أو Imports مكسورة.
